# planning — 想法的成熟管線（idea → roadmap → 詳規 → 執行）

[WORKFLOWS](../WORKFLOWS.md)｜[INDEX](../INDEX.md)

一個想法從「要不要做」到「動工」的四個階段收在**同一條管線**，不拆成四個工作流——免得卡在「這算 idea 還是 roadmap」。

**何時用**：使用者說「記個想法」「這件事以後要做」「排進 roadmap」「幫我規劃」。
**何時不用**：三兩步的小事直接做；已有計畫且在動工 → 照 `plans/` 那份計畫做，進度記 [SESSION-LOG](../SESSION-LOG.md)。

## Done when

- idea / roadmap：下方對應表多一列，或既有列的狀態欄更新。
- 詳規：`plans/` 底下的計畫檔有「目標 / 不做什麼 / 步驟表 / 收尾」四段，且步驟表每列的「時間點」欄非空；執行完移 `plans/archive/`。

## 階段

| 階段 | 回答的問題 | 落點 |
|------|-----------|------|
| **idea** | 要不要做？ | 下方「想法」表，一列一句 |
| **roadmap** | 會做，何時？ | 下方「roadmap」表 |
| **詳規** | 怎麼做？ | `plans/` 一份計畫一檔（如 `plans/2026-q4-n3.md`）：目標 / 不做什麼 / 步驟表 / 收尾 |
| **執行** | — | 照那份計畫動手，進行中的狀態寫 [SESSION-LOG](../SESSION-LOG.md) 一行；要使用者親自做的寫 [WAIT_USER](../WAIT_USER.md) |

## 想法（要不要做）

| 想法 | 一句話 | 狀態（想想 / 會做→搬進 roadmap / 不做＋原因）|
|------|--------|--------------------------------------------|
| `grammar/` 匯出成 Anki 卡片 | 一條文法一張卡，例句在正面、文法名在背面 | 想想（等文法筆記滿 50 條再評估，現在手動維護還划算）|
